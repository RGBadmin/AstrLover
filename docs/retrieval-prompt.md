# 检索造词提示词

跟视觉解析提示词配套：**那份决定库里存的是什么词，这份决定拿什么词去搜。**
两份不对齐，索引建得再好也搜不出来。

- 提示词正文：面板 →「设置」→「相册」→ **检索造词提示词**（可改，改完即时生效）
- 默认值在 `astrlover/album/prompts.py`
- 用在 `want_photo`：她只说"为什么想发"，由轻量模型照这份把它翻成检索词

输出格式（`keywords` / `want` / `rating` / `season` 四个字段）由 `tools.py`
在提示词后面追加，不在可编辑的那份里——调提示词是常事，调坏解析就白瞎一次调用。

---

## 五条规则，各对着一个真实机制

**一、只用库里真有的词。** 库里的文字是视觉解析写的，只有它用的词搜得到。
写「下面」「私处」一张都搜不到——实测下来「下面」还会被拆字回退成「面」，
命中一堆无关的图。

**二、多给词不会缩小结果。** 词面检索是 IDF 加分制、**不取交集**
（`album/search.py`）：给六个词只对上两个，那张照样出得来，只是排得靠后。
这一条必须明写——不写的话模型会本能地"少给几个词免得搜不到"，正好搞反。

**三、按段给词。** 描述被切成四段各转一个向量（`album/embed.py: split_layers`），
检索时四段各比一次取最大。整篇三千字里九成是身体细节，环境那两百字在全文
向量里几乎看不见；切开之后环境词才撞得上环境段。所以环境、身体衣着、动作体液
三类各给几个，才打得全。

**四、分级和季节走参数，不写进检索词。** 「骚」「露」这些字在描述正文里到处
都是，当检索词是纯噪声。

**五、画面描述写成陈述句。** `want` 拿去做语义比对，「我想找一张…」里每个字
都进了向量。写成视觉解析会写出来的那种句子最像。

## 分词词典要跟着一起对齐

检索侧分词（`album/search.py: segment`）拿 `TAG_VOCAB` 做正向最大匹配：
在词典里的词整体切出来，不在的退二元滑窗，「蝴蝶逼」会被切成「蝴蝶」「蝶逼」，
命中率差一大截。

词典原先只从标签候选值凑，所以只有「淫水拉丝」这种复合形态，裸词「淫水」不在
里面——可正文写的就是裸词，人搜的时候打的也是裸词。现在把视觉解析提示词末尾
那份词表（身体 / 动作 / 体液 / 状态）也收进词典（`vision/tags.py` 的
`_BODY_WORDS` 那几组）。

**改视觉提示词的用词时，这三处要一起看：** 视觉提示词、`tag_schema.py` 的候选值、
`tags.py` 的补充词表。`tests/test_search_prompt.py` 会验证提示词里教的词
确实切得出来——脱节了测试会挂，不会悄悄失效。
